# Support Resolution Engine — Sales Kit

## 1. Offer
A human-supervised support automation service for repetitive customer-support tickets.

Workflow:
1. Ticket arrives.
2. Intent/category is identified.
3. Customer/order context is retrieved.
4. Relevant policy/context is applied.
5. Draft answer is generated.
6. Confidence/risk is assessed.
7. Safe cases can be resolved; uncertain or risky cases are escalated to a human.

We sell the business outcome: faster responses, fewer repetitive handling minutes, and measurable support efficiency. We do not sell an API.

## 2. First paid pilot
Recommended starting offer:
- Duration: 2–4 weeks
- Pilot price: USD 1,000
- One support workflow
- Human approval remains required for uncertain/risky cases
- Baseline captured before customization
- Controlled test set used before production rollout

Alternative commercial range: USD 500–2,000 depending on scope and integration work.

## 3. What the client receives
- Workflow assessment
- Support-ticket classification
- Policy-grounded response drafting
- Customer/order context retrieval using agreed data sources
- Confidence and escalation logic
- Pilot dashboard/report
- End-of-pilot KPI report
- Production recommendation

## 4. What is not included in the base pilot
- Full CRM/helpdesk replacement
- Unlimited custom integrations
- Autonomous handling of high-risk refunds, legal, medical, financial, or security cases
- Guaranteed savings or guaranteed automation percentage
- Customer-data processing before the appropriate access/security terms are agreed

## 5. Success metrics
Measure baseline and pilot performance for:
- First-response time
- Human minutes per ticket
- Safe-resolution rate
- Escalation rate
- Cost per resolved ticket
- Classification accuracy
- Draft acceptance/edit rate
- API/infrastructure cost per ticket

No ROI claim is made until baseline data is available.

## 6. Buyer
Primary: Head of Support / Customer Operations / COO.
Secondary: Support Director, CX Director, Operations Manager.

Best prospects have high ticket volume, repetitive questions, an existing helpdesk/CRM, and a clear support-cost problem.

## 7. Discovery questions
Ask only what is needed:
1. How many support tickets do you handle per month?
2. What are the top 5 repetitive ticket categories?
3. What helpdesk/CRM/order system do you use?
4. What percentage currently requires a human response?
5. What is the biggest support bottleneck: response time, staffing cost, backlog, or consistency?

## 8. Sales sequence
### Step 1 — Problem-first outreach
Do not lead with AI, APIs, or technical architecture.

Message structure:
- identify repetitive support workload
- state the measurable problem
- offer a short demonstration
- propose a pilot only after confirming fit

### Step 2 — 15-minute discovery
Confirm volume, repetitive categories, systems, current workflow, and baseline metrics.

### Step 3 — 3-minute demo
Show one ticket going from intake to classified intent, retrieved context, grounded draft, confidence, and escalation.

### Step 4 — Paid pilot
Send the proposal and invoice. Recommended payment: 50% at kickoff and 50% at pilot completion, unless the client requires another structure.

### Step 5 — Pilot
Use synthetic/sample data first where possible. Connect real customer data only after access/security requirements are agreed.

### Step 6 — ROI review
Compare baseline with pilot metrics. If the results are credible, propose production pricing.

## 9. Production pricing hypothesis
Starting point:
- Base: USD 750–2,500/month
- Plus usage where appropriate, such as per ticket/resolution
- Integration/setup fee when material integration work is required

Final price is based on volume, workflow complexity, integration scope, and measured value.

Verify the account's actual receiving/withdrawal capabilities before accepting a client payment.

Do not put payment credentials, API keys, or banking secrets in GitHub.
